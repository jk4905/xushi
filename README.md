# 煦食

把想吃的，做成这一餐。

一个人的家庭做饭工具：选菜 → 买菜 → 阅读完整做法 → 明确完成这一餐。包含 **H5 和原生微信小程序**，后续产品需求默认同时维护两个版本。

## 项目结构

```text
h5/                          浏览器版页面、样式、业务模型及回归
miniprogram/                 微信原生 WXML / WXSS / JavaScript
  core/                     生成的共享模型 + 微信存储等平台适配
  scripts/sync-h5.cjs        生成 / 只读检查共享模型
docs/                       双端维护约定与交付验证
.github/workflows/check.yml 双端回归和模型一致性检查
```

本仓库是两端代码的唯一维护入口。历史设计稿、调研、iOS 实验与开发者工具私人配置不在交付范围内。

## 运行 H5

直接用浏览器打开 `h5/weekend-menu-prototype.html`。也可以从仓库根目录启动本机服务：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory h5
```

然后打开 <http://127.0.0.1:8765/weekend-menu-prototype.html>。浏览器本地数据属于当前来源；从旧文件地址或端口迁移时，先在旧版导出备份，再在新版导入。

## 运行微信小程序

在官方微信开发者工具中导入 **`miniprogram/`**，使用已有开发者权限，选择「不使用云服务」后编译。无需安装 npm 运行依赖。项目 AppID 是公开标识，不包含 AppSecret。

详细操作见 [小程序说明](miniprogram/README.md)。更换本地工程目录后，模拟器缓存可能与旧目录不同；先从旧工程导出，再导入新工程，不清除旧缓存。

## 修改与验证

开发检查使用 Node.js 22+，无第三方测试依赖，不需要 `npm install`。

```sh
# 共享模型 / 原始菜谱有修改后，生成小程序对应文件
npm run sync

# 两端回归 + 共享模型一致性 + 小程序工程结构
npm test

# 只读检查：模型未同步时失败，不自动改文件
npm run check
```

H5 与小程序的界面独立实现。`sync` 只负责共享模型和原始菜谱，**不自动同步界面、存储适配或动效**。每次需求变更都要完成两端对应实现、两端回归与平台验收，规则见 [双端维护约定](docs/dual-platform.md) 和 [AGENTS.md](AGENTS.md)。

## 当前边界

- 两端都在本地保存数据，通过兼容的 JSON 备份手动迁移；没有云数据库或跨设备同步。
- 菜谱链接保存原地址；没有自动解析外部页面、视频或 AI 生成配方。
- 西芹按原配方保留；未知用量与缺失做法不补造。
- 自动化测试验证逻辑与结构，不等于 iPhone 键盘、安全区、动画手感或真实做饭可用性通过。

当前整理和验证范围见 [验证记录](docs/validation.md)。推送 GitHub 不代表已发布微信小程序或部署 H5。
