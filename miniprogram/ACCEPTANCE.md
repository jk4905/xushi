# 煦食 · 可独立执行的验收脚本

环境：微信开发者工具稳定版、iPhone 微信。先导出已有记录；测试可使用空的开发者工具本地缓存。不要清除真实用户数据。

1. **首次使用。** 导入工程并编译。首页应只有安排第一餐与餐次入口，不默认产生记录。进入菜谱，添加原始三道菜谱；连续点击不重复添加。牛肉有原文 10 步及示意图，西兰花/米饭显示未记录做法，西芹仍保留。
2. **安排与采购。** 回做饭，安排一餐，选三道菜，餐名日期留空，开始准备应直接进入买菜。重复点击同一材料 4 次：它的屏幕位置不移动，状态恢复未选。长按培根标为家里已有；切 Tab 回来，从接着准备进入，状态保留。
3. **直接下厨。** 点一次「开始做饭」即显示完整做法，不要求核对数量或确认配方。用料缺失应有提示，不能假装所有用料已收集。
4. **独立恢复。** 牛肉滚到第 3 段；切西兰花（缺失做法页）；再切回牛肉，应回到原位置。另用手动录入的一道多段测试菜滚到第 2 段，切 Tab、回做饭、接着做饭；两菜应各回各的位置。重新编译后复查。不要为此编造原西兰花做法。
5. **本餐调整。** 在牛肉中段进入用料，改一项实际用量并保存，应回原餐原位置。再改备注，返回但不保存，去采购勾选另一项，回来恢复草稿并保存：新采购勾选应保留。原菜谱材料不变。
6. **失败恢复。** 在开发者工具调试器临时将 wx.setStorageSync 替换成抛错函数（记录原函数后操作，见下方），新建餐/编辑菜谱/保存用料都不得返回或显示成功，输入保留。恢复函数后重试，只出现一份新记录。结束故障注入后重编译。
7. **明确完成。** 滚到最后不自动完成。点击「这餐做好了」并取消，仍可继续。再次点击并确认，首页不再显示这餐；全部餐次的做过中应有它。复做后是新餐，原餐用量/备注保留、新采购全部未勾选。
8. **备份回读。** 导出 JSON，并保存到自己可找回的位置；导入该文件，数量与记录应一致。导入无效 JSON 不能清空现有数据。仅复制到剪贴板不代表已有安全备份。
9. **iPhone 外观与触控。** 在正常字号和系统放大字号下，检查长菜名、长做法、多行备注、最后一个材料、屏幕安全区。输入时键盘不盖住输入和可达保存按钮；收起键盘后主操作/Tab 正常恢复。连续滚动、换菜和点勾选不能跳格。检查 VoiceOver 的菜名、状态与按钮名称。

故障注入仅用于开发者工具测试（本地缓存环境）：

```js
const xushiOriginalSetStorage = wx.setStorageSync;
wx.setStorageSync = function () { throw new Error('xushi-test-quota'); };
// 执行一次保存并观察失败；随后立即恢复：
wx.setStorageSync = xushiOriginalSetStorage;
```

若当前工具不允许替换该 API，则跳过手动故障注入，使用 `npm test` 中的存储故障测试；在记录里标注手动故障场景未验证。

记录格式：设备/微信版本、基础库、操作路径、预期、实际结果、截图或屏幕录制、是否可重复。自动化结果与真机结果分开写。
