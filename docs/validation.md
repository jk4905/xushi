- H5 的 8 个运行 / 回归文件与迁移来源逐文件字节比较一致。

### 验证边界

- **逻辑 / 结构：** 本轮实际执行上述检查。
- **浏览器 / 微信模拟器：** 本轮没有在新目录重新操作；代码未改动界面，不将旧目录的运行证据算作新目录验收。
- **iPhone / 键盘 / 安全区 / 动效手感：** 本轮未验证。
- **真实做饭可用性：** 本轮未观察。
- **数据迁移：** 代码目录迁移不移动用户本地数据。旧浏览器来源和旧小程序工程缓存须先导出，再在新位置导入；没有代用户执行数据迁移。
- **应用发布：** 仅提交源代码；没有部署 H5 或上传 / 发布微信小程序。

### 独立复验

1. 克隆仓库，安装 Node.js 22+；不装依赖直接运行 `npm test`，应以 0 退出。
2. 在根目录运行 README 的本机 HTTP 命令，打开 H5；在微信开发者工具导入 `miniprogram/`。
3. 在两端分别执行 [主流程验收](../miniprogram/ACCEPTANCE.md) 中的安排、采购、连续阅读、切菜恢复、本餐调整、取消完成与备份回读。H5 使用浏览器对应入口；微信故障注入仅用于小程序，不在生产数据上操作。
4. 记录两端的实际路径与结果；未操作的步骤标为未验证，不用本地测试通过代替真机验收。
